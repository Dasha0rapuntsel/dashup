# ML/LLM-подход

## Распределение задач по технологиям

| Задача | Первый вариант | Следующий шаг |
|---|---|---|
| Схема, PII, запретные категории | правила | правила + локальный NER |
| Тема и очередь | keyword baseline | TF-IDF + logistic regression или небольшой encoder |
| Поиск статьи | лексическое совпадение | hybrid BM25 + embeddings |
| Текст ответа | утверждённый шаблон | grounded LLM по найденной статье |
| Право на auto-close | policy engine | остаётся policy engine |
| Дубли при инциденте | не входит в PoC | embeddings + online clustering |

LLM не должен решать, можно ли закрывать платёжный или другой рискованный тикет. Его полезная роль — аккуратно переформулировать найденный материал. Во внешний API можно передавать только masked text и минимальный фрагмент approved KB; raw PII, секреты и полный профиль пользователя запрещены.

## Данные

Для первой модели нужны 8–12 недель истории: redacted text, канал, назначенная очередь, итоговая категория и финальная резолюция. Для качества ответов дополнительно нужны версия статьи, принятый или исправленный черновик, CSAT и reopen через 7 дней.

Разметка строится на коротком гайде с двумя независимыми разметчиками и разбором расхождений. Train/test делятся по времени и incident cluster: копии одного массового сбоя не должны оказаться с обеих сторон. Перед обучением проверяются PII, пропуски, перекос классов, языки/каналы и leakage из полей, появившихся после решения оператора.

## Baseline и критерии выбора

PoC уже даёт baseline: правила + лексический поиск + шаблон. Следующим разумно проверить TF-IDF с logistic regression — он быстрый, дешёвый и объяснимый. Более тяжёлая модель оправдана только заметным приростом качества на редких формулировках.

Offline gates перед пилотом:

- recall high-risk категорий ≥ 99%;
- precision safe auto-close ≥ 97%;
- Recall@3 поиска ≥ 90%;
- ни одной критической утечки PII на red-team наборе;
- проверенная калибровка confidence (ECE/Brier), а не произвольный softmax score.

Для маршрутизации смотрим macro-F1 и recall каждого класса, для retrieval — Recall@3/MRR@3, для черновика — groundedness, точность ссылок и acceptance оператором. Общая accuracy не подходит: она может скрыть ошибки в редкой, но опасной категории.

## Низкая уверенность

Система выбирает `ESCALATE`, если вероятность ниже порога, top-1 и top-2 слишком близки, язык или тема неизвестны, статья слабо подходит, правила конфликтуют либо найден prompt injection. Итог оператора становится обучающим feedback только после выборочного QA — иначе ошибки начнут усиливать сами себя.

Порядок проверки: offline → две недели shadow → две недели suggest → небольшой A/B одной allowlist-темы. Переходить к следующему этапу можно только после прохождения safety gates.

# SafeDesk AI — безопасная автоматизация поддержки

SafeDesk AI разбирает входящий тикет, скрывает персональные данные, определяет тему и риск, находит ответ в проверенной базе знаний и принимает одно из двух решений: ответить автоматически или передать обращение оператору.

Основной принцип: **при недостаточной уверенности система не принимает автоматическое решение и передаёт тикет оператору**.

## Ценность решения

- Пользователь быстро получает ответ на простой вопрос и не ждёт в общей очереди.
- Оператор не тратит время на повторяющиеся действия и сразу видит тему, найденную статью и причину эскалации.
- Бизнес высвобождает часть операторской ёмкости и устойчивее обрабатывает всплески до 10–20 тысяч тикетов за 10 минут.

## Реализованный объём

PoC — небольшой локальный Python-сценарий без внешних библиотек, API-ключей и LLM. Он выполняет всю основную цепочку:

`тикет → PII masking → тема и риск → поиск по базе знаний → решение → аудит`

В коде реализованы:

- маскирование номера карты, телефона и email;
- простой и объяснимый baseline для темы и риска;
- поиск по трём утверждённым статьям базы знаний;
- policy gates: PII, риск, низкая уверенность или слабая статья всегда ведут к оператору;
- audit log без исходного текста тикета, но с версией использованной статьи;
- пять автоматических тестов.

## Запуск

Нужен Python 3.10+.

```bash
python app.py --demo
python -m unittest discover -s tests -v
```

В Windows, если команды `python` нет, используйте `py -3`.

Отдельный тикет:

```bash
python app.py --text "Как отключить email-уведомления?" --ticket-id T-100
```

## Два демонстрационных пути

**Happy path.** «Как отключить email-уведомления?» → тема `notifications` → низкий риск → статья `KB-001` → `AUTO_CLOSE` и готовый проверенный ответ.

**Risky path.** «С карты списали деньги дважды, номер 4111…» → номер маскируется → тема `payment` → высокий риск → `ESCALATE`. Пользователь не получает автоматический ответ.

## Границы реализации

В реализованный PoC не входят очередь событий, CRM-интеграция, обученная ML-модель, embeddings, внешний LLM, интерфейс оператора и production-инфраструктура. Эти компоненты представлены только на уровне целевого дизайна.

Ограничения PoC: только русский язык, маленькая тестовая база знаний, эвристический confidence и одна разрешённая для автозакрытия тема — `notifications`. Это достаточно, чтобы проверить логику решения, но недостаточно для production-запуска.
